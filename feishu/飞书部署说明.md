# 飞书版部署说明

飞书版 = 原版 + 两样东西（都写在 `feishu/overlay.js`，**不改动 `src/` 任何文件**）：

1. **「导出 CSV」按钮** —— 把记录拍平成「一行 = 一套卷」的平表，可直接导入飞书多维表格
2. **飞书 WebView 适配** —— 安全区域（刘海屏/底部横条）、禁止下拉回弹、撑满高度

产物：`feishu/dist/考公看板-飞书版.html`（单文件，已内联图表库，零外部请求）

```bash
python feishu/build_feishu.py     # 重新构建飞书版
```

# 路线 A：飞书多维表格（推荐先试，零代码）

**为什么需要 CSV**：你原来的 xlsx 是「5 行一块、带合并单元格」的纵向结构，
多维表格导入时是**把每一列变成一个字段**，直接导进去会变成一堆垃圾。所以先用
飞书版的「导出 CSV」拿到平表。

## 步骤

1. 打开飞书版页面 → 点 **「导出 CSV」** → 得到 `考公套卷-平表-YYYY-MM-DD.csv`
2. 飞书中：**云文档 → 新建 → 导入 → 上传这个 CSV** → 自动生成一张多维表格

导入后你会得到 **67 个字段**（一行 = 一套卷）：

```
日期 · 试卷 · 分数 · 平均分 · 击败比(%)
政治理论题数 · 政治理论正确数 · 政治理论正确率(%) · 政治理论平均正确率(%) · 政治理论用时(分钟)
常识……（六模块各 5 列）
逻辑填空/片段阅读/语句表达 · 图形推理/定义判断/类比推理/逻辑判断（子模块各 4 列）
总题数 · 总正确数 · 总正确率(%) · 总用时(分钟)
```

> 字段多是为了不丢信息。用不上的列在多维表格里右键隐藏或删掉即可。

3. **想看统计** → 新建**仪表盘** → 添加折线图组件，X 轴选「日期」，
   Y 轴选「政治理论正确率(%)」等 → 就跑出趋势图了。
   统计字段（求和/平均/最大/最小）只对**数字字段**生效——CSV 里的数值列都已是数字。

4. **想让多人各自只看自己的数据** → 开启多维表格**高级权限**，
   权限能细到**记录（行）**级，配合「创建人」字段可实现"每人只看到自己录入的行"。

## 这条路的已知限制

| 限制 | 说明 |
|---|---|
| 图表参考线 | 仪表盘不保证支持「目标线 / 黄色下限线」这种参考线，需要用辅助字段变通 |
| 移动端 | 能**查看**仪表盘，但**不能创建/编辑**仪表盘组件（编辑数据表本身正常） |
| 公式字段 | 各模块正确率建议自己再建「公式字段」，这样录入新数据时自动算，不用回来改 CSV |

# 路线 B：H5 网页应用（保留现有界面，几乎不改代码）

把飞书版页面挂成一个飞书应用，用户点开就是飞书内全屏 H5。

## 步骤

1. **先有个飞书企业**（开放平台要求开发者必须是企业用户；自己新建一个团队也算）
2. 把 `feishu/dist/考公看板-飞书版.html` 部署到任意 **https** 静态托管上（GitHub Pages 即可）
3. 飞书**开发者后台** → 创建**企业自建应用** → 左侧「添加应用能力」→ 添加 **「网页应用」**
4. 在「网页应用配置」里填**主页地址**（桌面端 / 移动端都要填，就用上一步拿到的 https 链接）
5. **发布**：正式版要企业管理员审核；开发阶段建议先用**测试版应用**（免审核、配置立即生效），
   验证没问题后再同步到正式版，只需提交一次审核

## ⚠️ 一个误解要先打消

**挂进飞书不会让数据变成跨设备同步的。** 页面还是存在本机浏览器的 localStorage 里，
只是入口搬进了飞书。要真同步，还是得加后端。

所以路线 B 的价值是：**移动端有个原生入口，不用给用户发网址**。
如果这一条对你没价值，那就直接用路线 A。

# 共同的注意事项

## 数据隐私属性会变

- 路线 A（多维表格）：成绩上传到**飞书（字节）的服务器**。如果用公司飞书，
  **管理员在权限允许下可能看到你的数据**。
- 路线 B（H5）：数据仍只在本机，隐私属性不变。

这是取舍，不是技术问题。

## 原版不受影响

飞书版是与原版**并行**的产物，共用 `src/` 里的业务代码：

- 原版 `考公练习追踪看板.html`（本地双击用）—— **没有** CSV 按钮，行为与以前完全一致
- 原版 GitHub Pages 部署 —— 同样不受影响
- 飞书版改了 `feishu/overlay.js` 后，只需重跑 `python feishu/build_feishu.py`

改业务逻辑（统计口径、界面）仍然只改 `src/` 一处，两个版本同时受益。

## 验证情况

`devtest/test-feishu.js` 会在真实 Chrome 里跑完整流程：
增量功能是否生效、导出的 CSV 能否被标准 RFC4180 解析器解回来（含逗号/引号的转义）、
67 列数值逐项核对、按日期升序、零外部请求、无控制台报错。

**未验证**：飞书客户端内的实际打开效果（需要在飞书里配好应用才能真正试）；
多维表格的导入效果（需要你把 CSV 拖进去试）。这两步都得你亲自点一次。
