# 飞书部署说明

**现在只有一个版本**：同一份产物既用于本地双击，也用于飞书 H5。原先「原版 + overlay」
的两变体结构已取消——既然飞书版本来就是超集，就没必要维护两份。

产物：`考公练习追踪看板.html`（单文件，已内联图表库，零外部请求）
与 `docs/index.html` 内容相同。

```bash
python build.py     # 构建（一条命令，只出一个版本）
```

其中与飞书相关的两块能力已经并入 `src/`：

1. **「导出 CSV」按钮** —— 把记录拍平成「一行 = 一套卷」的平表，可直接导入飞书多维表格
   （代码在 `src/js/csv-export.js`）
2. **WebView 适配** —— 安全区域（刘海屏/底部横条）、禁止下拉回弹、撑满高度
   （代码在 `src/css/base.css`，桌面浏览器上无副作用）

# 路线 A：飞书多维表格（推荐先试，零代码）

**为什么需要 CSV**：你原来的 xlsx 是「5 行一块、带合并单元格」的纵向结构，
多维表格导入时是**把每一列变成一个字段**，直接导进去会变成一堆垃圾。所以先用
飞书版的「导出 CSV」拿到平表。

## 步骤

1. 打开飞书版页面 → 点 **「导出 CSV」** → 得到 `考公套卷-平表-YYYY-MM-DD.csv`
2. 飞书中：**云文档 → 新建 → 导入 → 上传这个 CSV** → 自动生成一张多维表格

导入后你会得到 **67 个字段**（一行 = 一套卷）：

```
日期 · 试卷 · 分数 · 平均分 · 击败比(%)
政治理论题数 · 政治理论正确数 · 政治理论正确率(%) · 政治理论平均正确率(%) · 政治理论用时(分钟)
常识……（六模块各 5 列）
逻辑填空/片段阅读/语句表达 · 图形推理/定义判断/类比推理/逻辑判断（子模块各 4 列）
总题数 · 总正确数 · 总正确率(%) · 总用时(分钟)
```

> 字段多是为了不丢信息。用不上的列在多维表格里右键隐藏或删掉即可。

3. **想看统计** → 新建**仪表盘** → 添加折线图组件，X 轴选「日期」，
   Y 轴选「政治理论正确率(%)」等 → 就跑出趋势图了。
   统计字段（求和/平均/最大/最小）只对**数字字段**生效——CSV 里的数值列都已是数字。

4. **想让多人各自只看自己的数据** → 开启多维表格**高级权限**，
   权限能细到**记录（行）**级，配合「创建人」字段可实现"每人只看到自己录入的行"。

## 这条路的已知限制

| 限制 | 说明 |
|---|---|
| 图表参考线 | 仪表盘不保证支持「目标线 / 黄色下限线」这种参考线，需要用辅助字段变通 |
| 移动端 | 能**查看**仪表盘，但**不能创建/编辑**仪表盘组件（编辑数据表本身正常） |
| 公式字段 | 各模块正确率建议自己再建「公式字段」，这样录入新数据时自动算，不用回来改 CSV |

# 路线 B：H5 网页应用（保留现有界面，几乎不改代码）

把飞书版页面挂成一个飞书应用，用户点开就是飞书内全屏 H5。

## 前提：先拿到一个 https 地址

飞书「网页应用」的**主页地址必须是 https**。而且只要**不调用飞书 JSAPI**，
就**不需要配置「H5 可信域名」、不需要验证域名所有权**——任意一个 https 地址都能直接填。

### 做法一：把 Pages 来源切到 feishu 分支（最快，推荐先试）

仓库 Settings → Pages → Source 选 `Deploy from a branch` → 分支选 **`feishu`**、
文件夹选 **`/(root)`** → Save。等 1~2 分钟，`https://cuizhiyu712.github.io/kg_viewer/`
就是飞书版。

**这个切换不会丢数据**：localStorage 按「协议+域名+端口」隔离，而 GitHub Pages 的
origin 是 `https://cuizhiyu712.github.io`（**不含仓库名和路径**），所以换分支、换仓库名
都不影响已存的数据。URL 也完全不变。

代价：部署来源变成 feishu 分支，以后改完源码要重新构建并更新那个分支的 `index.html`
（做法见文末「更新已部署的飞书版」）。

### 做法二：换一个国内可达性更好的托管（github.io 在大陆不稳时用）

⚠️ **先实测再决定**：用你的手机（大陆网络，不要挂代理）打开
`https://cuizhiyu712.github.io/kg_viewer/`。如果能秒开，做法一就够用；
如果慢或打不开，说明 github.io 在你这边的网络环境不可靠——飞书 H5 也是从公网加载页面，
同样会慢，那就该换托管。

可选：

| 托管 | 大陆可达性 | 门槛 |
| --- | --- | --- |
| 腾讯云 CloudBase **静态托管** | 好（境内节点） | 免费环境不支持自定义域名，只能用平台给的默认域名；默认域名官方标注「仅开发测试」 |
| 腾讯云 COS / 阿里云 OSS | 好 | 绑自定义域名要 **ICP 备案** |
| Cloudflare Pages / Vercel | 一般 | 免备案，但国内可能慢（`*.pages.dev` 之类子域名尤其不稳） |

只想「能给飞书填个地址就行」的话，CloudBase 静态托管 + 默认域名是最省事的一条：
把 `考公练习追踪看板.html` 传上去，它会给你一个 https 地址。

## 步骤（拿到地址之后）

1. **先有个飞书企业**（开放平台要求开发者必须是企业用户；自己新建一个团队也算）
2. 按上面拿到 https 地址
3. 飞书**开发者后台** → 创建**企业自建应用** → 左侧「添加应用能力」→ 添加 **「网页应用」**
4. 在「网页应用配置」里填**主页地址**（桌面端 / 移动端都填同一个 https 链接）
5. **发布**：正式版要企业管理员审核；开发阶段建议先用**测试版应用**（免审核、配置立即生效），
   验证没问题后再同步到正式版，只需提交一次审核

## 更新已部署的版本

改完 `src/` 后，重新构建并同步到 feishu 分支：

```bash
python build.py
git checkout feishu
cp "考公练习追踪看板.html" index.html
git commit -am "更新部署产物"
git push
git checkout main
```

推完等 1~2 分钟 Pages 自动重建。浏览器可能缓存旧版，用 **Ctrl+F5** 强刷。

## ⚠️ 一个误解要先打消

**挂进飞书不会让数据变成跨设备同步的。** 页面还是存在本机浏览器的 localStorage 里，
只是入口搬进了飞书。要真同步，还是得加后端。

所以路线 B 的价值是：**移动端有个原生入口，不用给用户发网址**。
如果这一条对你没价值，那就直接用路线 A。

# 共同的注意事项

## 数据隐私属性会变

- 路线 A（多维表格）：成绩上传到**飞书（字节）的服务器**。如果用公司飞书，
  **管理员在权限允许下可能看到你的数据**。
- 路线 B（H5）：数据仍只在本机，隐私属性不变。

这是取舍，不是技术问题。

## 为什么合成一个版本

原先的做法是「`src/` 保守原版 + `feishu/overlay.js` 运行时叠加出飞书版」。但飞书版本就是
原版的超集（只多不少），维护两份产物没有收益，反而容易「改了一边忘了另一边」。

现在合成为一个：

- 只有一条构建路径：`python build.py`
- 本地双击、飞书 H5、GitHub Pages 用的都是同一个文件
- URL 与 origin 都没变，所以**已有用户数据不受影响**（localStorage 按
  「协议+域名+端口」隔离，跟产物内容无关）

## 验证情况

`devtest/test-feishu.js` 会在真实 Chrome 里跑完整流程：
增量功能是否生效、导出的 CSV 能否被标准 RFC4180 解析器解回来（含逗号/引号的转义）、
67 列数值逐项核对、按日期升序、零外部请求、无控制台报错。

**未验证**：飞书客户端内的实际打开效果（需要在飞书里配好应用才能真正试）；
多维表格的导入效果（需要你把 CSV 拖进去试）。这两步都得你亲自点一次。
